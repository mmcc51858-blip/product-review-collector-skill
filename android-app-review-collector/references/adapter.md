# 页面适配与字段规则

## 任务配置

复制下面结构为本次任务 JSON。`package`、`list_resource_id`、`body_left`、`sku_regex`、`viewport` 必须由现场 XML/截图核实。`sku_left` 可选，已观察到规格固定列时填入，用于排除含斜杠的“图/视频”等筛选标签。屏幕坐标基于真机原始像素，不能将 1080×2354 当作所有手机的尺寸。

```json
{
  "platform": "抖音",
  "product_name": "本次指定商品",
  "source_url": "用户提供的完整商品链接",
  "sort": "综合",
  "filters": "全部评价、全部款式",
  "package": "com.ss.android.ugc.aweme",
  "list_resource_id": "com.ss.android.ugc.aweme:id/e1p",
  "body_left": 44,
  "sku_left": 177,
  "sku_regex": "【|/",
  "viewport": [0, 242, 1080, 2122],
  "scroll_x": 550,
  "scroll_start_y": 1950
}
```

这些值来自 2026-11-13 的一次抖音页面实测，App 升级可失效。此适配按列表直接子块的顺序读取“买家与日期”“规格与正文”“媒体”“浏览与有用”等块，排除列表外重复的商品评价预览。不能按全屏所有 TextView 拼接评论。

未指定条数时默认全部采集。`end_texts` 是可选字符串数组，只填现场实际观察并确认的列表结束提示原文；未核验时保持空数组或省略，不凭经验填“没有更多了”。无结束标记且连续无新增时保留断点，报告全量未完成。显式页数或时间预算也只代表运行预算，不代表全量完成。

识别日期要覆盖“5天前”“1个月前”“3小时前”和明确日期。新屏的第一条可能没有完整头部，此时保持字段缺失，或用已验证同一评价的另一屏补齐，不继承上一位买家的日期。昵称用哈希匿名标识，不收集主页或联系方式。

## 核验重点

- 先确认商品归属，再确认评价总数、排序及筛选。评价总数仅记录页面标注，不做完成数量。
- 列表资源 ID 匹配一个节点才允许连续采集，多个或没有都停止。
- 正文与规格位于同一已观察结构块时才配对。商品预览、推荐卡片、卖家文案不能算评论。
- UI 文本存在不代表完整显示，检查是否有省略、展开或被遮挡。实际缺失就注明，勿补写。
- 图片保存多屏时，以正文出现的评价作为映射依据。仅媒体块的屏幕与之前评价关联前，核对头像/卡片边界及连续性；不把下一位买家的图片归给上一条。

## 异常判定

`unauthorized` 由用户确认手机授权；`offline` 由用户恢复连接；无列表先看当前页面，不盲目点击。页面有验证、风险或异常提示时先停止输入。XML 能读而截图图片空白，应等待正常加载，仍失败则记录缺图。系统策略拒绝某操作不得用另一条等效命令绕过。
